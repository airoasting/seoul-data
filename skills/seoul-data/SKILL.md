# seoul-data

서울시 공공데이터로 답한다. 도구는 7개이고 질문의 종류로 고른다.

## 1. 어떤 도구를 쓰나

| 질문 | 도구 | 첫 호출 예 |
|---|---|---|
| 장소가 지금 어떤가 (혼잡, 날씨, 도로, 행사, 주차) | `place_now` | `{"place": "성수동"}` |
| 여러 곳 비교 | `place_now` | `{"places": ["홍대", "성수동", "강남역"], "sections": ["population"]}` |
| 역에 열차가 언제 오나 | `subway_arrivals` | `{"station": "강남", "line": "2호선"}` |
| 따릉이가 남았나 | `bike_stations` | `{"query": "여의나루"}` |
| 미세먼지 나쁜 순 | `dataset_query` | `{"dataset": "OA-2219", "sort": "-PM"}` |
| 실거래 평균과 건수 | `dataset_query` | 4절의 예 |
| 그 밖의 서울시 데이터 | `dataset_search` → `dataset_query` | `{"query": "무더위쉼터"}` |
| 인증키 이야기 | `key_setup` | `{}` |

`place_now`는 서울시가 지정한 121곳만 된다. 자치구 단위는 없다. 그 밖의 동네를 물으면 후보 중에서 고르거나 사용자에게 묻는다. 실시간 도시데이터와 지하철 도착은 `dataset_query`로 부를 수 없다(`USE_TOOL` 오류가 전용 도구를 알려 준다).

## 2. 답할 때 지킬 것

1. **`notices`를 답에 반영한다.** 일부만 훑었다, 필터가 반영되지 않았다, 장소를 이렇게 해석했다, 응답을 덜어 냈다는 말이 있으면 사용자에게 알린다.
2. **기준 시각을 말한다.** 실시간 값은 `meta.as_of`와 함께 말한다. 인구 값은 20~30분 전 집계인 경우가 많다. "지금"이라고 하지 말고 "21:05 기준"이라고 한다.
3. **단위를 확인한다.** `fields`에 서울시 명세의 설명이, `meta.units`에 단위가 있다. 실거래 `THING_AMT`는 만원이다. 147963은 약 14억 8천만 원이다. 주차장의 `CUR_PRK_CNT`는 주차된 차량 수다. 남은 자리는 `CPCTY`에서 뺀다.
4. **인구는 범위로 말한다.** `AREA_PPLTN_MIN`~`MAX`는 통신 데이터 추정치다. 한 숫자로 줄이지 않는다.
5. **평균과 합계를 직접 계산하지 않는다.** `dataset_query`의 `metrics`와 `group_by`를 쓴다. `meta.scan_complete`가 false면 전체가 아니라고 말한다. `meta.rows_missing`이 있으면 그만큼 빠진 어림값이라고 말한다("약 6,600곳"). `meta.rows_missing_pct`가 5를 넘으면 그 숫자를 답으로 쓰지 말고 한 번 더 부른다. 건수를 세거나 견줄 때 `offset`으로 직접 넘기며 세지 않는다. 행 순서가 호출마다 달라질 수 있다.
6. **`meta.filters_checked`를 본다.** "불일치"가 있으면 그 결과를 해당 필터의 값이라고 말하지 않는다.
7. **출처를 붙인다.** `meta.source_url`을 답 끝에 단다.

## 3. 체험 모드 (인증키 없음)

키가 없으면 처음 5행, 장소는 광화문·덕수궁, 지하철은 서울역의 앞 5건만 보인다. 이때 도구는 `SAMPLE_PLACE_ONLY`, `SAMPLE_STATION_ONLY`, `SAMPLE_LIMIT` 오류를 낸다.

- 오류에 딸려 온 `available`이나 `preview`를 사용자가 물은 대상의 답으로 쓰지 않는다. 5행으로 평균이나 건수를 내지 않는다.
- 사용자에게 무료 인증키가 필요하다고 알리고 발급 방법을 안내한다. data.seoul.go.kr 로그인, 인증키 신청.
- 일반 인증키 하나로 지하철 도착을 뺀 전부가 열린다. 지하철 도착은 실시간 지하철 인증키를 따로 받는다(일반 키는 받아 주지 않는다).
- 지하철 키가 없어도, 그 역이 121곳 안에 있으면 `place_now {"place": "강남역", "sections": ["subway"]}`가 일반 키로 그 주변 역의 도착 정보를 준다.
- 사용자가 키를 알려 주면 `key_setup`의 `general` 또는 `subway`에 넣는다. 키가 대화에 남는 것을 꺼리면 터미널 명령 `python3 assets/mcp_server.py --setup`을 안내한다.

## 3-1. 지하철 도착을 말할 때

- 행은 노선과 방향별로 가까운 열차부터 놓여 있다. 같은 방향의 첫 행이 다음 열차다.
- 남은 시간은 `eta_now_sec`(지금 기준)를 쓴다. 없으면 `status`의 문장("전역 도착", "[3]번째 전역" 등)을 그대로 풀어 말한다. "전역"은 바로 앞 역이다.
- `stale`이 붙은 행은 이미 지나갔을 수 있다. 다음 열차로 말하지 않는다.
- 방향은 `heading`의 "○○방면"으로 말한다. 2호선은 순환선이라 양방향 행선지가 같을 수 있다.
- `last_train`은 막차일 때만 나온다. 막차 시각표는 이 데이터에 없다.
- 조건에 맞는 열차가 없으면 안내에 "지금 이 역에 있는 것"이 나온다. 그중 하나로 다시 부른다.

## 4. 범용 조회

1. `dataset_search`로 OA-번호를 찾는다. 키워드는 짧은 명사가 잘 맞는다. 검색어 없이 부르면 대표 데이터셋과 필터가 나온다.
2. 필터를 걸어야 하면 `dataset_describe`로 필터 이름과 값 형식을 본다. 앞부분만 볼 때는 건너뛴다.
3. `dataset_query`로 부른다.

조건을 거는 두 가지 길을 구분한다.

- `filters`. 서울시 서버가 거른다. 빠르지만 정확 일치(일부는 앞부분이나 부분 일치)만 된다. 문화행사의 `TITLE`은 부분 일치다. `DATE`는 그날 끝나는 행사를 주므로 "그날 하는 행사"를 찾는 데 쓰지 않는다.
- `where`. 받은 행에서 이 서버가 거른다. 범위(`CTRT_DAY>=20260801`), 부분 일치(`TITLE~재즈`), 빈 값(`RTRCN_DAY=`)이 된다. 날짜는 꼴이 달라도(`2026-11-14`, `20261114`, 시각이 붙은 값) 같은 날짜로 보고 조건의 길이만큼만 견준다. 빈 값은 범위 조건에 맞지 않는다. 한 번에 10,000행을 훑고 `scan`으로 50,000행까지 늘린다.

먼저 `filters`로 좁히고 그 안에서 `where`를 쓴다(제목에 "재즈"가 든 행사는 `filters {"TITLE": "재즈"}`가 `where`보다 빠르고 완전하다). 다 못 훑었으면 `scan`을 늘리거나 `meta.next_scan_offset`을 `scan_offset`에 넣어 이어 훑는다. 조각을 합칠 때는 count와 sum만 더한다. 평균은 sum과 count를 더해 다시 나누고, 중앙값은 조각끼리 합칠 수 없으니 그렇게 말한다. 자치구 여러 곳을 비교할 때는 자치구마다 따로 부른다. 자치구 하나의 음식점 같은 인허가 데이터는 `dataset_search "종로구 일반음식점"`으로 자치구별 데이터셋을 찾는다.

### 예. "마포구 올해 아파트 매매 평균"

```json
{"dataset": "OA-21275",
 "filters": {"RCPT_YR": "2026", "CGG_NM": "마포구"},
 "where": ["BLDG_USG=아파트", "RTRCN_DAY="],
 "metrics": ["count", "avg:THING_AMT", "median:THING_AMT"]}
```

`RTRCN_DAY=`는 취소되지 않은 거래만 남긴다. 답에는 건수, 평균과 중앙값(억 단위로 바꿔서), 기간과 조건(접수연도, 취소 제외), `scan_complete` 여부를 싣는다. 최근 석 달로 좁히려면 `where`에 `"CTRT_DAY>=20260814"`를 더한다.

### 예. "이번 주말에 하는 전시"

`DATE` 필터로는 진행 중인 전시를 찾을 수 없다. 기간으로 건다.

```json
{"dataset": "OA-15486", "filters": {"CODENAME": "전시"},
 "where": ["STRTDATE<=2026-11-15", "END_DATE>=2026-11-14"],
 "fields": ["TITLE", "PLACE", "DATE", "USE_FEE", "ORG_LINK"], "limit": 20}
```

값에 `/`가 든 분류(`전시/미술`)는 `/` 앞부분만 넣는다.

## 5. 오류가 오면

`error.next`가 다음 할 일이다.

| code | 뜻 | 할 일 |
|---|---|---|
| `PLACE_AMBIGUOUS` | 장소 후보가 여럿이거나 비슷한 이름만 있다 | `candidates`에서 고르거나 사용자에게 묻는다 |
| `PLACE_UNKNOWN` | 121곳에 없다 | `place_now`를 인자 없이 불러 목록에서 가까운 곳을 고른다 |
| `USE_TOOL` | 전용 도구로 봐야 하는 데이터다 | `tool`에 적힌 도구로 다시 부른다 |
| `ERROR-336` (지하철) | 지하철 서버가 요청을 받지 않았다 | 잠시 뒤 다시. 역 이름이 틀리면 보통 빈 결과와 "비슷한 이름" 안내가 온다 |
| `SUBWAY_KEY_NEEDED` | 실시간 지하철 인증키가 없다 | 발급을 안내한다. `next`에 일반 키로 되는 길이 있으면 그것을 쓴다 |
| `BAD_INPUT` | 인자나 필터 이름이 틀렸다 | `next`의 쓸 수 있는 이름을 보고 고친다 |
| `SITE_CHANGED` | 열린데이터광장 화면이 바뀌었다 | 사용자에게 알린다. 서비스명을 알면 `service`와 `path_args`로 우회한다 |
| `ERROR-500` | 서울시 서버 오류 | 서비스명을 확인하고, 맞으면 서울시 쪽 문제라고 알린다 |
| `NETWORK` | 연결 실패나 시간 초과 | 잠시 뒤 한 번 더. 반복되면 알린다 |

## 6. 하지 않는 것

- 통계 데이터셋(DT로 시작)은 API가 없다. `dataset_search`를 `api_only: false`로 불러 열람 주소(`url`)를 안내한다.
- 길찾기, 소요 시간, 요금 계산은 하지 않는다.
- 응답에 없는 숫자를 만들어 내지 않는다. 데이터가 없으면 없다고 말한다.

서울시 API의 세부 동작은 [references/api-notes.md](../../references/api-notes.md)에 있다.
